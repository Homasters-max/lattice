# S0-47 · Параллельный `verify` — `scripts/verify.mjs` и кэши

Инструмент контура проверки (PLAN.md, раздел 8, «Контур проверки»); вне лимита SL-06.

## Зачем

`npm run verify` идёт шагами через `&&`: на `main` тесты 37 с, `lint` (eslint с типами) 13.6 с, typecheck 3.3 с, build 1.8 с, прочее ~2 с — около минуты; на 13 циклах прогонов было ~150. После S0-40 тесты быстрее, и шаги по очереди стали главной статьёй. Параллельные шаги и кэши от классификатора S0-42 не зависят и дают выигрыш каждому прогону сразу (решение владельца 2026-10-08).

## Объём

Входит:
- **`scripts/verify.mjs`** без новых зависимостей: шаги `lint:ids`, `plan:check`, `lint:eol`, `typecheck`, `lint`, `build`, `test` — параллельно; вывод каждого буферизуется и печатается по порядку шагов; последняя строка — JSON `{ok, steps: [{step, ms, exit}], log}`; полный лог — в файл; код выхода — ненулевой, если упал хоть один шаг;
- **кэши** в `.lattice/` (в `.gitignore`): `eslint --cache`, `tsc --incremental`;
- `npm run verify` зовёт `scripts/verify.mjs`; CI по-прежнему зовёт шаги по отдельности.

Не входит: выбор тестов по изменённым путям — S0-42.

## Тесты и фикстуры

- Упавший шаг: ненулевой код выхода, шаг назван в JSON с `exit`, его вывод — в логе целиком.
- Все шаги зелёные: `ok: true`, порядок вывода — порядок шагов.

## Готово, когда

- [ ] `npm run verify` идёт параллельно и печатает итог одной JSON-строкой
- [ ] кэши eslint и tsc в `.lattice/`
- [ ] замер до и после — в описании PR
- [ ] `npm run verify` зелёный
