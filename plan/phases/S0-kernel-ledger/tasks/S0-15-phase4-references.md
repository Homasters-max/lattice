# S0-15 · Фаза 4 — ссылки, метки, фрагменты, memo, уникальность

## Зачем

Граф знания без висячих ссылок: цель каждой ссылки существует в `after` (RF-03). Фаза читает `after`, потому что тип и блок, на который ссылаются, могут прийти в том же коммите.

## Объём

Входит — фаза 4 apply над `after`:
- **visible set** (RF-01): свои namespaces и `core`; namespaces библиотек — через составной view (S0-22); ссылка вне visible set — отказ;
- **разрешение** (RF-02, RF-05): floating — current revision; floating на alias — каноническая сущность; pinned — как написано; ссылка на `retired` — не отказ (finding — S1);
- **существование** (RF-03): цель в tail или в том же коммите; ссылка на run в S0 отклоняется с RF-08, пока evidence не декодируется (S1);
- **фрагменты** (RF-04, TY-09): путь есть в типе цели, ключ map — в теле; операция порта адресуется фрагментом;
- **аннотация `ref`** (KR-19): цель — тип `to` или его подтип; `pin` соблюдён;
- **цели ссылок контракта** (TY-06, TY-12) по `after`: формы данных контракта (`input`, `output`, `params` у `stage`, операции `port`) — abstract-тип (G-35); `contract` у `judge-adapter` — ревизия `std/judge` (G-37);
- **внешние ссылки** (RF-06): существование не проверяется;
- **метки** (RF-07, TR-03): из `std` (TY-16) или объявленные в namespace;
- **`knowledge` → `runtime`** (RF-08): только через процитированные runs;
- **пути `memo`** (TY-10): есть во входном типе операции;
- **уникальность** (LG-19): в namespace автора, только среди сущностей в use; отмена `retired`/`alias` и ревизия типа, меняющая `unique`, перепроверяют;
- **alias** (TR-29, G-11, G-32): у неотозванного `alias` есть `value`; канонический `id` в том же namespace, звезда, не цепочка.

## Тесты и фикстуры

Фикстуры trigger/pass на каждое правило списка; плюс: ссылка на тип и блок из того же коммита проходит; фрагмент на несуществующий ключ map отклоняется; отмена `retired` вызывает конфликт уникальности.

## Готово, когда

- [ ] фикстуры всех правил списка — trigger и pass
- [ ] visible set — интерфейс, который S0-22 расширяет библиотеками

## Риски и заметки

- RF-05 частично S1: отказа нет, а finding появится вместе с механизмом проверок.
- От S0-07: поле `extends` мета-типа — `format: ref` без аннотации `ref` и без метки: метки `extends` в словаре TY-16 нет (G-26). RF-07 для него — решение этой задачи: исключение мета-типа или метка.
- От S0-08: формы данных контракта (`input`, `output`, `params` у `stage`, операции `port`) ссылаются на `core/type@1`; что цель — abstract-тип (TY-06), проверяет эта фаза по `after` (G-35). `contract` у `judge-adapter` сужен только до `std/port@1`; что цель — ревизия `std/judge` (TY-12), проверяет эта фаза по `after` (G-37).
- От S0-08: аннотация `ref` стоит только там, где правило называет один тип цели; `decides`, `checked_by`, `items` у `domain` и `section`, `of.entity` у `retired` и `alias`, `value` у `alias` и `for` у `core/session` — `format: ref` без `ref` и без метки, метка — в `description` (G-31). RF-07 для этих полей — решение этой задачи: метка из TY-16 или исключение.
- От S0-08: схема `alias` не выражает, что у неотозванного `alias` есть `value` (TR-29): `revoked` необязателен, `oneOf` различает ветви только по `const`; отказ — эта фаза вместе с остальными условиями `alias` (G-32).
