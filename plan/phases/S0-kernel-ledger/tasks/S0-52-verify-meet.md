# S0-52 · Тест параллельного `verify` без 2-секундного окна

Инструмент контура проверки; нестабильный тест, замеченный при пересборке S0-51 на `main` 2026-10-08.

## Зачем

`test/tools/verify.test.ts`, случай «runs the steps at once: every step has started before any ends», нестабилен под нагрузкой полного `npm run verify` на Windows. Шаг-заглушка с `delay: "meet"` ждёт, пока все шаги отметятся в `started/`, но не дольше 2 с, и печатает `met <шаг> <видел>`. Запуск семи процессов `npm run` → `node` под нагруженным прогоном тестов бывает дольше 2 с — тогда `видел` меньше семи и ожидание `met <шаг> 7` падает (один раз при пересборке S0-51; отдельно и при повторе зелёный). Падение — от окна, а не от `scripts/verify.mjs` (PR-11).

## Объём

Входит:
- окно ожидания шага-заглушки — предохранитель `SAFEGUARD_MS` (`test/support/budget.ts`, S0-41, CONVENTIONS §8.5), а не 2 с;
- что показывает тест, не меняется: каждый шаг видит старт всех семи, прежде чем кончиться.

Не входит: правка `scripts/verify.mjs`.

## Тесты и фикстуры

- Прежние ожидания `verify.test.ts` без изменений.
- Стабильность: `npm run verify` зелёный несколько раз подряд.

## Готово, когда

- [x] окно шага-заглушки — `SAFEGUARD_MS`, ожидание случая прежнее
- [x] `npm run verify` зелёный несколько раз подряд

## Как сделано

- `test/tools/verify.test.ts`: в скрипте `stand` окно `meet` — `SAFEGUARD_MS` (30 с) вместо 2000 мс; ожидание `met <шаг> 7` у каждого шага прежнее. Окно — предохранитель: шаг кончается, как только увидел старт всех семи (≈1 с отдельно).
- Без окна вовсе шаг-заглушка при последовательном `verify.mjs` не кончился бы никогда и пережил бы прогон тестов: таймаут vitest не убивает внуков `npm run`. Окно ограничивает жизнь таких процессов.
- Воспроизведение до правки: из трёх `npm run verify` на `main` один упал на этом случае — 5240 мс, `met … 7` не напечатали `lint:ids`, `lint:eol`, `typecheck`, `build`. После правки — пять прогонов `npm run verify` подряд зелёные.
- Тест по-прежнему ловит последовательный запуск: `verify.mjs`, временно переписанный на шаги по очереди, — случай падает за 30 с.

## Отступления

- **Таймаут случая не поднят.** В наброске — таймаут выше окна, чтобы последовательный запуск падал на ожидании `met <шаг> 7`, а не на таймауте. Не выходит: по очереди каждый шаг ждёт окно, семь окон — 210 с, и любой разумный таймаут истекает раньше. Последовательный запуск падает по таймауту `SAFEGUARD_MS`; прежде он падал через 2 с на `met lint:ids 1`. Ловит тот же класс, сообщение беднее.
- Описание теста в `S0-47-parallel-verify.md` («или через 2 с») поправлено под окно.
