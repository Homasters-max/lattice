# S0-44 · Мутации в `prove --ready` — выживших решает executor

Инструмент контура проверки (PLAN.md, раздел 8, «Контур проверки»); вне лимита SL-06.

## Зачем

33 из 40 блокирующих находок на 13 циклах — `untested`: «тест не падает, если проверку сломать». Spec находил их своими мутациями — 58 мин и 41% времени ревью; harness писался заново в 15 запусках из 23; каждая такая находка стоила круга исправлений. Факт «тест падает, если проверку убрать» устанавливает исполнение, а не модель (PR-09), и до ревью, а не после (решение владельца 2026-10-08).

## Объём

Входит:
- **`npm run prove --ready`** (S0-42) добавляет мутации изменённых hunk'ов `src/`; операторы:
  - убрать отказ, убрать операнд `&&`/`||`, сдвинуть границу `<`/`<=`;
  - поле отказа → `null` или константа (`intent`, `expected`, `place.path` и др.);
  - убрать поле из входа hash или подписи, подставить другой аргумент того же типа;
  - убрать вызов сортировки или компаратор.

  Тесты мутанта — затронутые test-sets и фикстуры (S0-42); пул процессов; кэш по `(hash мутанта, hash test-set)` — мутант не гоняется повторно, пока его входы те же. Отчёт: мутант, оператор, исход `killed|survived|budget-exceeded`, какой тест убил;
- **`mutate --at <файл:строка>`** — один мутант на строке, для ревьюера;
- **выжившие**: executor до ready и fixer до push решают каждого — `killed` (тест добавлен, коммит), `equivalent` или `deferred` (с причиной); решения — поле `mutants` в `out.json`; `dl check` отказывает выходу, где выживший не решён; решённого `dl` помнит по hash мутанта и не выносит снова;
- **Spec**: отчёт и решения — в brief; ось сверяет решения и ищет то, чего мутация не видит; вне отчёта мутирует только `mutate --at`;
- **контракт**: тела `.claude/agents/executor.md` и `fixer.md` — «готово, когда `npm run prove --ready` зелёный и выжившие решены», поле `mutants` в схеме выхода; `reviewer-spec.md` — «читай отчёт; вне отчёта — только `mutate --at`»; `plan/dev-loop.md` — схема `mutants`; `plan-task` шаг 5 — `--ready`.

Не входит: мутации в воротах и параллельно с ревью; мутации вне `src/`; мера силы test-set (LT-31) — отчёт evidence для ревью, без вердикта.

## Как сделано

- **Файлы**: `scripts/mutants.mjs` — мутанты изменённых hunk'ов `src/` (операторы `refusal`, `logical`, `boundary`, `refusal-field`, `hash-input`, `sort`; «подставить аргумент того же типа» — по типу из type checker TypeScript); его же зовёт `dl check`. `scripts/mutate.mjs` — прогон, пул, кэш `.lattice/mutate/cache.json`, отчёт `.lattice/mutants.json` и `npm run mutate -- --at <файл:строка> [--operator <оператор>]`. `seedOf` и `filtersOf` переехали из `prove.mjs` в классификатор `scripts/paths.mjs`, `flagOf` — в `scripts/verify.mjs`: `prove` грузит `mutate` только при `--ready`, и два модуля не импортируют друг друга.
- **Тесты мутанта** — test-sets, чьи тесты импортируют или запускают его файл (`reach` в `select` у `prove`); фикстуры входят, когда их тесты достают файл, — отдельно не добавляются. Перед мутантами группа test-sets гоняется без мутанта: красная — `prove` красный; её время × 3, не меньше 10 с, — бюджет мутанта. Пул — копии рабочего дерева во временной папке системы, `node_modules` — ссылкой.
- **`npm run prove --ready`**: npm отдаёт флаг скрипту как `npm_config_ready`; `-- --ready` тоже работает. Выживший `prove` не краснит.
- **`dl check`** требует отчёт только когда в изменённых hunk'ах `src/` на head есть мутанты: отчёт на head без незакоммиченных правок, все мутанты названы, каждый `survived` решён. `killed` — с `commit` ветки, и отчёт на head показывает его убитым; `budget-exceeded` решения не требует. Решения — `state.mutants` по `id`; `init` переносит решения executor.
- **Spec**: в brief — `mutation` (сводка отчёта) и `mutants` (мутанты с решением, выжившие первыми).

## Тесты и фикстуры

- Каждый оператор: на фикстурном коде мутант, которого тест ловит, — `killed`; без такого теста — `survived`.
- Кэш: второй `prove --ready` без правок не гоняет мутантов; правка test-set гоняет их заново.
- `dl check`: выход executor с нерешённым выжившим отклонён; с решением — принят.
