# S0-44 · `mutate` — отчёт мутаций для ревью

Инструмент контура проверки (PLAN.md, раздел 8, «Контур проверки»); вне лимита SL-06.

## Зачем

В #30 ревьюер Spec и fixer каждый раз писали свой скрипт мутаций и гоняли мутантов по одному полным `vitest`: у fixer — 8.5 мин, у Spec — круг ревью. Факт «тест падает, если проверку убрать» устанавливает исполнение, а не модель (PR-09).

## Объём

Входит:
- **`scripts/mutate.mjs`**: мутанты — условия отказов жёстких проверок (вызов отказа с константой правила, CONVENTIONS §3) в изменённых hunk'ах `src/`; операторы — убрать отказ, убрать операнд `&&`/`||`, сдвинуть границу `<`/`<=`; тесты мутанта — затронутые test-sets и фикстуры (S0-42); пул процессов; `--at <файл:строка>` — один мутант. Отчёт: мутант, исход `killed|survived|budget-exceeded`, какой тест убил;
- **в цикле**: `dl gate` запускает мутации параллельно с ревью; Architecture и Standards стартуют сразу, Spec — с полем `mutations` в brief; решение по мутанту (`declined`, эквивалентен) `dl` помнит по hash мутанта и не выносит его снова;
- **контракт**: reviewer-spec — «читай отчёт `mutations`; вне отчёта — только `mutate --at`»; executor — `mutate` в самопроверке перед ready.

Не входит: мутации вне жёстких проверок и измерение силы test-set в дизайне — LT-31.

## Готово, когда

- [ ] `mutate` даёт отчёт по изменённым жёстким проверкам; `--at` работает
- [ ] Spec получает отчёт в brief; решённые мутанты не возвращаются
- [ ] контракт reviewer-spec и executor обновлён
- [ ] `npm run verify` зелёный
