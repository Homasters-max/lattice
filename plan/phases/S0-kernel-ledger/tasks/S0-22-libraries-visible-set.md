# S0-22 · Библиотеки и visible set

## Зачем

`std` — библиотека, как любая другая (TY-01, LG-44). Проект видит её через pins своего namespace. Без этого проектный namespace типа `std/namespace-policy@1` (Q-37) даже не создать.

## Объём

Входит:
- **pins** (LG-44): namespace проекта пинит в теле версию LATTICE (которая фиксирует `std`) и каждую библиотеку — имя, версия, hash;
- **библиотека** — npm-пакет с кодом и ledger; namespaces с префиксом владельца; библиотека не зависит от проекта; зависимости библиотек без циклов; имя namespace уникально в видимом наборе — конфликт отклоняется;
- **составной read view** (LG-45): свой fold плюс fold только для чтения каждого закреплённого ledger на его версии; fold библиотеки считается при загрузке пакета и кешируется в `.lattice/` по hash ledger и версии LATTICE; пакет везёт ledger и evidence, не строки;
- **постоянный hash** (LG-48): hash ledger библиотеки — константа её версии, проверяется при загрузке пакета и открытии store;
- **visible set** (RF-01, RF-02): свои namespaces, `core` и namespaces закреплённых библиотек; floating ссылка в библиотеку разрешается внутри её закреплённой версии; библиотека не ссылается на проект;
- **границы проектов** (PR-13): проект не пишет в чужой ledger и не ссылается на незаявленный.

Не входит: `upgrade` (LG-46 — SW), сборка настоящего `std` (S0-24).

## Тесты и фикстуры

- Фикстурные библиотеки собираются в тестах через apply на `memory` store.
- Ссылка в незаявленную библиотеку, конфликт имени namespace, неверный hash ledger, цикл зависимостей — отказы с rule ID.
- Кеш fold: второй запуск не пересчитывает, изменённый ledger пересчитывает.

- [ ] фаза 4 (S0-15) видит библиотеки через этот view без своих изменений
