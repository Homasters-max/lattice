# S0-02 · Соглашения кода, отказов и фикстур правил

## Зачем

Skeleton (S0-03) разнесёт эти соглашения по всем модулям; менять их потом — правка файлов skeleton и триггер аудита (ST-15). Поэтому они фиксируются до него, в одном документе `CONVENTIONS.md`.

## Объём

`CONVENTIONS.md` в корне, разделы:

1. **Данные.** Записи — замороженные простые данные и чистые функции, без класса на тип записи (ST-03). Типы `readonly`; `deepFreeze` на границах модулей в тестах. Имена — только термины LATTICE из 00 (ST-03): `record`, `intent`, `proposal`, `commit`, `fold`, `delta`, `row`, `view`, `standing`.
2. **Результаты.** Нарушение правила — значение, не исключение: `{ ok: true, value } | { ok: false, rejections }`. Исключение — только ошибка программы.
3. **Отказ** (LG-17): `{ intent, rule, message, path, expected, got }`, у дубликата ещё `id`. `rule` — литеральный тип `RuleId`; код ссылается на правило только через константу из реестра правил своего модуля.
4. **Жёсткие проверки** (ST-17): каждая объявляет rule IDs, которые она применяет. Раскладка фикстур: `test/fixtures/<RULE-ID>/trigger/<case>.json` и `.../pass/<case>.json`, у trigger — ожидаемый rule ID и путь. Fitness-тест: каждый ID из реестров имеет обе папки, и каждая папка — ID, который существует в `docs/design`.
5. **Порядок нарушений** `validate` (KR-21) и отказов apply — детерминированный: по `path`, затем по `keyword` или `rule`.
6. **Сообщения** — из шаблонов по rule ID (TR-40); язык — параметр; сообщение никогда не повторяет значение секрета (LG-20).
7. **Change units** (PR-15…PR-18, SL-06) — ссылка на навык `plan-task`, где процесс уже описан; `CONVENTIONS.md` его не повторяет.
8. **Чистота** (ST-04): что запрещено вне `adapters`, `assembly`, `cli` — список модулей платформы и глобалов, который проверит тест структуры.

## Шаги

1. Написать `CONVENTIONS.md`.
2. Набросать типы `RuleId`, `Rejection`, `Result` и пример реестра — они войдут в skeleton.
3. Согласовать с владельцем в PR.

## Готово, когда

- [ ] `CONVENTIONS.md` влит и покрывает пункты 1–8
- [ ] раскладка `test/fixtures/` и формат фикстуры описаны с примером
- [ ] skeleton (S0-03) может опираться на документ без новых решений

## Риски и заметки

- Не изобретать абстракций сверх правил: реестр правил — плоский список констант, не фреймворк (ST-02).
