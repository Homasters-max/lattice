# S0-26 · Codec — import md в proposal

## Зачем

Дизайн — первый корпус, который LATTICE читает о себе (SL-02, RM-03). Import превращает `docs/design` в блоки — так S0 проверяет, что модель знания выдерживает настоящий текст.

## Объём

Входит — `importMd(documents, at) → Result<Intent[]>` (`src/codec/import.ts`; `import` — слово языка): документ — `{path, bytes}`, `at` — время intents от вызывающего (порт `clock`), каждый intent — новая entity (`expected: null`) типа `std/<тип>@1`, в порядке документа:
- **блоки** (RM-Z03, LG-42): строка таблицы с ID — `clause`, `cells` в порядке колонок `{column, text}`, `column` — slug заголовка; абзац с ID — `prose`; fenced-блок с ID — `example` с `lang` и `text`; таблица или список без ID — поле `table` (`{header, rows}`) или `list` блока выше (G-01);
- **id** (RM-Z03): блок — `lattice/<ID в нижнем регистре>`; документ — `lattice/<имя файла без .md>`; секция — `<id документа>.<slug заголовка>`; slug заголовков и колонок таблиц — одна функция по RM-Z03;
- **секции**: `section` — `heading`, `level`, `items`: ссылки на блоки и подсекции по порядку и заголовок каждой таблицы, которую секция держит;
- **ссылки** (RM-Z03): каждый ID, упомянутый в тексте, и каждый ID диапазона `A…B` — floating ссылка в поле `refs`, метка `about`; ID внутри inline code — текст; текст хранится дословно. Текст блока — ячейки `clause`, текст `prose` и его поле `table` или `list`; текст `example` не разбирается (RM-Z03). Свой ID блока ссылкой не становится; `refs` отсортированы, повтор — одна ссылка; диапазон — концы одного префикса и вида (`KR-04…KR-13`), записанный от большего к меньшему — те же ID; блок без упоминаний — без `refs` (G-45);
- **один ID — один блок** (RM-01) и между документами: блок, чей ID есть в документе раньше, — отказ RM-01 по пути своего файла (строку parse не хранит в модели);
- **корпус** (GL-01, GL-02, PR-14): content blocks одного языка; язык не проверяется кодом — граница ревью;
- **вход** — байты файлов: каждый файл — `parse(bytes, place)` кодека (S0-25, S0-38) с местом файла `{ intent: null, path: "/docs/design/<файл>.md" }`, чтобы отказ назвал файл и строку; таблица clauses приходит одним элементом секции (`clauses`: `header` и `rows`), `id` блока — `idOf` модели (S0-38);
- **NFC** (KR-10): строки блоков кодек (S0-25) не нормализует и не проверяет; строка не в NFC — отказ KR-10 canon, когда блоки становятся proposal, а не тихая нормализация;
- итог — intents одного proposal; подпись и `expected` против tail — в `cli` (S0-21) или dev-скрипте (S0-29);
- codec берёт из `ledger` только тип `Intent` (`import type`; ST-01 разрешает `codec` → `ledger`), `test/codec/imports.test.ts` это держит; test set `codec` владеет `std/` (`scripts/paths.mjs`): тела проверяются по типам `std`.

Не входит: команда `import-md` (SW), owner act на весь импорт (LG-43 — SW).

## Тесты и фикстуры

- Число блоков по типам совпадает с моделью parse, а всех блоков — со счётом `lint-ids` (сейчас 458 определений, включая `Z`-блоки; `lint-ids` печатает только итог).
- Каждая ссылка из `refs` существует среди импортированных блоков (RF-03 на этом корпусе).
- Диапазон `KR-04…KR-13` даёт десять ссылок; ID в `` `KR-10` `` ссылкой не становится.
- Тела блоков проходят `validate` по типам из S0-08.
- Отказ кодека в одном из файлов называет путь этого файла и строку.
- Документ со строкой не в NFC — отказ KR-10, а не блок с нормализованным текстом.
