# S0-25 · Codec — модель md, разбор и канонический вывод

## Зачем

Главный критерий S0 — побайтный round-trip `docs/design` (SL-Z02). Главный риск (R1) — мелочи формата. Поэтому кодек — ранняя дорожка: сразу после skeleton, параллельно ядру, с эталонным тестом на всём корпусе с первого дня.

## Объём

Входит — чистый модуль `codec`, без ledger:
- **модель** канонического `md` (RM-Z03, LG-42): документ — заголовок уровня 1; секции `##`; абзац, начинающийся с ID и точки (`prose`); таблица — строка заголовка, разделитель `|---|` на каждую колонку, строки; строка с ID в первой ячейке — `clause`; таблица или список без ID сразу после блока, чей текст кончается на «:», — поле этого блока; fenced-блок с языком и ID — `example`, текст дословно;
- **разбор** `parse(bytes, path = "") → Result<Section>`: отказ на неканоническом входе, а не починка: CRLF, нет финального `\n`, две пустые строки подряд, пробелы в конце строки, разделитель не `|---|`, абзац без ID (RM-01), число ячеек не как у заголовка, ID не по грамматике (RM-02);
- **вывод** `print(document) → bytes`: одна пустая строка между блоками, таблицы с `|---|`, заголовки по уровню (LG-42);
- **содержимое ячеек** — дословно, включая `\|`, inline code, ссылки `[…](…)`, `…`, `—`, `→`;
- **списки** — по формату LG-42, хотя в корпусе их нет: модель и тесты есть, эталон их не проверяет.

Не входит: блоки и proposal (S0-26), export из view (S0-27).

## Тесты и фикстуры

- **Эталон**: для каждого файла `docs/design` — `print(parse(x)) === x` побайтно; тест в CI на ubuntu и windows с первой версии.
- Свойство: `parse(print(d))` равен `d` на сгенерированных документах.
- Каждый вид неканонического входа — отказ с rule ID (LG-42 или RM-01/RM-02) и строкой.

## Как сделано

Отступления от наброска — тоже в описании PR #20.

- **Интерфейс.** `parse(bytes, path = "")`: `path` — место документа во входе (CONVENTIONS.md §3), отказ — `${path}/<номер строки с 1>`, `intent: null`; S0-26 передаёт путь файла. Отказы собираются все, а не первый; одна строка — не больше одного отказа на правило. `print(document) → Uint8Array`.
- **Модель** (`src/codec/model.ts`): документ — `Section` уровня 1; у секции `items` по порядку — блоки `prose` (`text` — абзац целиком, с ID), `clause` (`cells` — все ячейки, ID первой), `example` (`lang`, `text` — байты между строками ограждения), заголовок таблицы `header` (за ним — её `clause`) и подсекции. Поле блока — `table` (`{header, rows}`) или `list`, как называет LG-42; блоки ещё не записи — это S0-26.
- **Мелкая форма `md`**, о которой LG-42 молчит, — по рекомендации **G-25**: абзац — одна строка; список — строки `- <текст>`, один уровень, только как поле; ровно один пробел вокруг ячейки; открытие fenced-блока — три обратных апострофа, `lang`, пробел, ID; построчные проверки внутри него не действуют; «кончается на ":"» — текст `prose`, последняя ячейка `clause`, текст `example` без последнего перевода строки; поле у блока одно.
- **Отказы сверх списка «Объём»** — та же каноническая форма LG-42: документ не начинается заголовком уровня 1 или в нём второй такой заголовок; блоки без пустой строки между ними; ячейка не в одном пробеле; fenced-блок не закрыт или открыт не строкой из трёх обратных апострофов, `lang`, пробела и ID; строка списка не `- <текст>`. Таблица, список и fenced-блок без ID — RM-01, как абзац; второй блок с тем же ID в документе — тоже RM-01 («One ID — one block»), на строке второго.
- **Байты не UTF-8** — отказ KR-10 функцией ядра `decodeUtf8`: её экспортирует точка входа `kernel`, кодек проверку не повторяет. NFC строк кодек не проверяет — это canon (KR-10), когда import (S0-26) пишет блоки.
- **RM-02** кодек проверяет как грамматику ID по виду блока: строка таблицы — правило (RM-01), её ID — `<PREFIX>-<NN>`; fenced-блок — example, его ID — `<PREFIX>-Z<NN>`; абзац — правило или проза, ID любого из двух видов. Что префикс — префикс документа, по-прежнему проверяет `lint-ids` (S0-01): кодек не знает имени файла.
- **Файлы**: `src/codec/` — `model.ts`, `lines.ts` (строки и куски между пустыми строками), `table.ts`, `ids.ts`, `parse.ts`, `print.ts`, `rules.ts` (LG-42, RM-01, RM-02); тесты — `test/codec/` (`corpus`, `parse`, `print`, `property`, `imports` — импорты `src/codec/` только `kernel` и свои файлы: ST-01 разрешил бы и `ledger`), фикстуры — `test/fixtures/{LG-42,RM-01,RM-02}/` и `KR-10/trigger/md-not-utf8.json`, строка `md` в `test/fixtures/checks.ts`.

## Риски и заметки

- Корпус сейчас: заголовки `#` и `##`, 8 fenced-блоков, все с ID, разделители только `|---|`, `\|` в 5 строках, списков нет, все файлы — LF с финальным переводом строки. Кодек не должен быть шире, чем нужно, кроме списков, которые называет LG-42.
- `lint-ids` (discussion/tools) уже проверяет RM-01 и RM-02 на тексте; кодек повторяет эти проверки на модели, а не вызывает скрипт.
