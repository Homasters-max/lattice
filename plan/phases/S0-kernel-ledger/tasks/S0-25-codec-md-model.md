# S0-25 · Codec — модель md, разбор и канонический вывод

## Зачем

Главный критерий S0 — побайтный round-trip `docs/design` (SL-Z02). Главный риск (R1) — мелочи формата. Поэтому кодек — ранняя дорожка: сразу после skeleton, параллельно ядру, с эталонным тестом на всём корпусе с первого дня.

## Объём

Входит — чистый модуль `codec`, без ledger:
- **модель** канонического `md` (RM-Z03, LG-42): документ — заголовок уровня 1; секции `##`; абзац, начинающийся с ID и точки (`prose`); таблица — строка заголовка, разделитель `|---|` на каждую колонку, строки; строка с ID в первой ячейке — `clause`; таблица или список без ID сразу после блока, чей текст кончается на «:», — поле этого блока; fenced-блок с языком и ID — `example`, текст дословно;
- **разбор** `parse(bytes) → document | rejections`: отказ на неканоническом входе, а не починка: CRLF, нет финального `\n`, две пустые строки подряд, пробелы в конце строки, разделитель не `|---|`, абзац без ID (RM-01), число ячеек не как у заголовка, ID не по грамматике (RM-02);
- **вывод** `print(document) → bytes`: одна пустая строка между блоками, таблицы с `|---|`, заголовки по уровню (LG-42);
- **содержимое ячеек** — дословно, включая `\|`, inline code, ссылки `[…](…)`, `…`, `—`, `→`;
- **списки** — по формату LG-42, хотя в корпусе их нет: модель и тесты есть, эталон их не проверяет.

Не входит: блоки и proposal (S0-26), export из view (S0-27).

## Тесты и фикстуры

- **Эталон**: для каждого файла `docs/design` — `print(parse(x)) === x` побайтно; тест в CI на ubuntu и windows с первой версии.
- Свойство: `parse(print(d))` равен `d` на сгенерированных документах.
- Каждый вид неканонического входа — отказ с rule ID (LG-42 или RM-01/RM-02) и строкой.

## Готово, когда

- [ ] все 17 файлов `docs/design` проходят эталон побайтно
- [ ] неканонический вход отклоняется с номером строки и rule ID
- [ ] модуль чистый и импортирует только `kernel`

## Риски и заметки

- Корпус сейчас: заголовки `#` и `##`, 8 fenced-блоков, все с ID, разделители только `|---|`, `\|` в 5 строках, списков нет, все файлы — LF с финальным переводом строки. Кодек не должен быть шире, чем нужно, кроме списков, которые называет LG-42.
- `lint-ids` (discussion/tools) уже проверяет RM-01 и RM-02 на тексте; кодек повторяет эти проверки на модели, а не вызывает скрипт.
