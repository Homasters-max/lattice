# S0-45 · Ревью по hunk'ам — вердикт оси как evidence

Инструмент контура проверки (PLAN.md, раздел 8, «Контур проверки»); вне лимита SL-06.

## Зачем

На 13 циклах 13 из 23 повторных кругов запущены не блокирующими находками — tidy (8), решением владельца, rebase — и снова гоняли все оси; нашли они одну блокирующую находку (S0-25 W3-S1), и та лежала в hunk'е дельты. Ось Architecture за 20 запусков не нашла ничего. Каждый круг ждёт ворот, хотя ворота были красными 1 раз из ~57. Ревью устроено как тесты: вердикт — evidence с ключом, ревьюируется только то, что его не имеет (решение владельца 2026-10-08).

## Объём

Входит:
- **вердикт оси** — evidence с ключом (ось, hunk): файл и hash текста hunk'а в head; состояние цикла хранит вердикты; hunk, которого коснулась правка, теряет вердикт;
- **`dl wave`**: круг ревьюирует hunk'и без действующего вердикта — только осями, чьи триггеры (классификатор S0-42) они задевают; находки с ответом получают статусы (роль `verifier`); режимы `full`, `delta`, `close`, `status` в `scope.mjs` заменяются этим правилом; `conflicts` после пересборки остаётся;
- **Architecture по триггерам**: новый или изменённый экспорт, новый модуль или порт, правка `test/support/`, файл из `test/structure/skeleton-files.txt`; иначе опись `closure-check.md` остаётся самопроверкой executor;
- **старт круга**: Architecture и Standards стартуют вместе с `dl gate`, Spec — когда готов отчёт `prove --ready` (S0-44); красные ворота отменяют вердикты только hunk'ов, которые задело исправление;
- **brief ревьюера** (S0-48) — hunk'и, которые оси выбраны, и причина выбора каждого;
- **tidy внутри `answer`**: если в круге есть блокирующие находки, fixer `answer` в том же запуске решает и советы, и находки `late` — `fixed`, `deferred` или `declined`, как в tidy; отдельный круг `tidy` остаётся только после круга без блокирующих находок, где есть советы;
- **контракт**: `plan/dev-loop.md` «Круги», «Ничего не теряется» и схемы; тела агентов (S0-48): `fixer.md` — `answer` решает и советы, `verifier.md` — без режимов `close`, `status`, `delta`, `reviewer-architecture.md` — запуск по триггерам, все ревьюеры — только hunk'и из brief; `.claude/skills/dev-loop/SKILL.md` «Переходы» и «Ворота».

Не входит: изменение осей и критериев `kind`.

## Как сделано

- **Hunk** — кусок diff ветки от merge-base с `origin/main` в `git diff -U0` (`plan/tools/dev-loop/scope.mjs`). Id — 12 знаков sha256 от пути, номера среди hunk'ов файла с теми же строками и строк `−` и `+`: номер строки в id не входит, правка выше по файлу вердикт не снимает. Файл без hunk'ов — переименование без правки, бинарный, режим — один hunk из строки статуса. `dl scope` печатает `hunks` с осями и причинами каждого; режима (`mode`) больше нет.
- **Триггеры осей**: Spec — всё, кроме генерируемого, если ветка меняет не только текст (как прежде: ветка из одного текста ревью не требует); Standards — код, тесты, конфигурация, `CONVENTIONS.md`; Architecture — экспорт в `src/`, `scripts/`, `test/support/`, новый модуль, новый порт, `test/support/`, skeleton. Прежние причины Architecture — `docs/design`, `gen/`, `package.json`, `src/assembly/`, файл добавлен или удалён — ушли; строка чистого кода, похожая на класс каталога обходов, Architecture не зовёт, её выносит `dl step selfcheck` (поле `bypass` у `scope`).
- **Вердикты** — `state.verdicts`: `{id hunk'а: буквы осей}` (`S`, `T`, `A`), только hunk'и текущего head — состояние в заголовке комментария не растёт с кругами. `merge` ставит вердикт оси за каждый id из поля `hunks` её brief'а, если hunk на head тот же; `state.unreviewed` — hunk'и head без вердикта нужной оси. Нет блокирующих находок, а `unreviewed` есть — `next: wave` (новый переход `decide`).
- **Задания**: ось — `hunks` (hunk'и без её вердикта, у каждого `reasons`), `verifier` — `answers` (статусы находок с ответом автора, новых находок нет); `conflicts` — как было. Спор автора тоже решает `verifier`: ось, на которой нашли находку, его больше не получает. Hunk'и дельты от прошлого head — материал `verifier`.
- **Старт с воротами**: `dl wave --early` пишет brief'ы Architecture и Standards, Spec — если `.lattice/mutants.json` снят на head без правок; `dl wave` после ворот добавляет в тот же круг остальных и не трогает начатых. Агент, начатый на прошлом head, остаётся: hunk'и, которые задело исправление красных ворот, его вердикта не получают и идут в следующий круг. `dl gate` перечитывает состояние перед записью: за прогон его мог записать `dl wave --early`.
- **`answer`** получает советы круга (`advice`) и решает их вместе с блокирующими; действия — `fixed`, `disputed`, `deferred`, `declined` и в `answer`, и в `tidy`. Отложить можно совет, находку `late` и решение владельца `task` или `gap` — блокирующую находку дельты нет.
- **Тесты**: случаи раздела ниже — `test/tools/dev-loop-hunks.test.ts`; `test/tools/dev-loop-scope.test.ts` переписан под hunk'и; ожидания `dev-loop-context`, `dev-loop-flow`, `dev-loop-clock`, `dev-loop-protocol`, которые называли режимы `full`, `delta`, `close`, `status` и прежние причины Architecture, — под новое правило задачи. Красные ворота в тесте — коммит исправления между `--early` и `dl wave`: `dl gate` гоняет `npm run verify`, его проверяют свои случаи.

## Тесты и фикстуры

- Правка одного hunk'а после круга: следующий круг ревьюирует только его и только осями его триггеров; вердикты прочих hunk'ов действуют.
- Дельта без триггеров Architecture не зовёт Architecture; новый экспорт — зовёт.
- Красные ворота после старта Architecture и Standards: исправление красного задевает hunk — его вердикты сняты, прочие сохранены.
- Круг с блокирующей находкой и советом: brief `answer` несёт оба, ответ без решения совета отклонён; после него круга `tidy` нет. Круг только с советом — круг `tidy`.

## Готово, когда

- [ ] вердикты хранятся по (ось, hunk); круг ревьюирует только hunk'и без вердикта
- [ ] режимы `full`, `delta`, `close`, `status` заменены одним правилом
- [ ] Architecture — по триггерам; Architecture и Standards стартуют вместе с воротами
- [ ] советы круга с блокирующими находками решает `answer`, отдельного `tidy` после него нет
- [ ] контракт цикла обновлён
- [ ] `npm run verify` зелёный
