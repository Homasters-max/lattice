# S0-49 · Фикстуры каждой пары «строка проверки × rule ID»

По разбору циклов `/dev-loop` 2026-10-08; в лимите SL-06.

## Зачем

ST-17 требует фикстуры trigger и pass у каждого rule ID жёсткой проверки. `test/fixtures/coverage.test.ts` проверяет это по папкам `test/fixtures/<ID>/` и не смотрит, через какую строку `test/fixtures/checks.ts` идёт фикстура; `runFixture` проверяет связь только в одну сторону — строка, названная в фикстуре, объявляет rule папки. В S0-36 Spec поймал строку `record`, объявившую KR-18 и KR-19 без своих фикстур (W1); этот класс на `main` есть и сейчас: `apply` → KR-10, `header` → KR-11, `store` → KR-10, `md` → KR-10 — без pass через свою строку.

## Объём

Входит:
- проверка в `test/fixtures/coverage.test.ts`: у каждой строки `checks.ts` для каждого ID из её `enforces` есть хотя бы одна фикстура trigger и одна pass, которые идут через эту строку; нарушение — отказ ST-17 с названной парой;
- недостающие фикстуры для четырёх пар.

Не входит: новые проверки в `src/`.

## Тесты и фикстуры

- Trigger: строка объявляет ID без pass через себя — отказ ST-17 с парой «строка × ID».
- Pass: у всех пар `checks.ts` есть trigger и pass.
