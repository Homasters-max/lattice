# S0-28 · Generate — TS-типы, валидаторы и конфиг линтера из типов

## Зачем

Источник правды контракта — блок; код получает сгенерированные из него TS-типы и валидаторы (ST-08, D8). Линтер получает лимиты из профиля качества (ST-09). Генератор нужен к S1, когда появятся реализации; в S0 он проверяется на `std`.

## Объём

Входит:
- **TS-типы и валидаторы** из типов (ST-08): по `type@n` — интерфейс и функция проверки, согласованная с `validate` ядра; abstract типы — интерфейсы для `$ref`; файлы в `gen/`, который git игнорирует, никогда не правятся руками;
- **`lattice export --gen`** (RT-32): из tail или из `after` dry-run;
- **CI** генерирует `gen/` перед type check;
- **профиль качества → конфиг ESLint** (ST-09): лимиты сложности, длины функции, вложенности, параметров, длины файла и правила чистоты; проверяется на фикстурном профиле (Q-08);
- генераторы — чистые функции (импортируют только `kernel`); запись файлов — в `cli` (ST-06).

Не входит: переключение репозитория на сгенерированный конфиг линтера (SW), code hash (RT-12 — S1).

## Тесты и фикстуры

- Дифференциальный тест: на примерах из S0-08 сгенерированный валидатор и `validate` ядра согласны в каждом случае.
- Сгенерированные типы `std` компилируются `tsc --noEmit`.
- Конфиг из фикстурного профиля совпадает с ожидаемым эталоном.

## Готово, когда

- [ ] `lattice export --gen` пишет `gen/` для `std`, и он компилируется
- [ ] дифференциальный тест валидаторов зелёный
- [ ] генератор конфига линтера покрыт тестом на фикстурном профиле
