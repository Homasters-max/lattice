# S0-48 · Минимальный контекст — brief несёт всё нужное роли

Инструмент контура проверки (PLAN.md, раздел 8, «Контур проверки»); вне лимита SL-06.

## Зачем

На 13 циклах контекст первого шага executor и fixer — 46k токенов, у ревьюеров — 7k: executor и fixer получают определения всех инструментов, MCP тоже. Ориентация executor до первой правки — медиана 23 шага и 5.3 мин, 35% его времени модели; 22% чтений — повторные; `CONVENTIONS.md` перечитан 17 раз. Fixer по своему определению читает `PLAN.md` фазы целиком (~25k токенов) на каждом из 35 запусков. Файлы читаются через `cat` и `sed` и правятся через Edit — 47 ошибок «File has not been read yet». Spec — 13 упавших `gh pr view`. Агент должен получать только нужное и в тот шаг, где оно нужно (решения владельца 2026-10-08).

## Объём

Входит:
- **слои контекста** — у каждого текста один дом:

  | Слой | Что | Дом |
  |---|---|---|
  | `tools` | инструменты роли | frontmatter агента |
  | `AGENTS.md` | общие нормы репо; грузится сам | `AGENTS.md` |
  | тело агента | неизменная инструкция роли: что делать, критерии, стоп-условия, точная схема `out.json` — какие поля, других нет | `.claude/agents/<роль>.md` |
  | brief | данные задачи, ≤ 15k токенов | собирает `dl brief` |
  | материал шага | раздел, нужный в одном шаге | `dl step <имя>` в момент шага |

  Текст одной роли — в теле агента; текст, общий с другими контекстами (`plan-task`, `closure-check.md`, `CONVENTIONS.md`, `docs/design`), — в своём доме, агенту его выдаёт `dl`. Роли уходят из `plan/dev-loop.md` в тела агентов; там остаются протокол обмена и схемы, которые проверяет `dl`, со ссылками на тела;
- **`tools`**: executor и fixer — Read, Edit, Write, Bash, Grep, Glob; reviewer-spec — Read, Grep, Glob, Bash, Write; reviewer-standards и reviewer-architecture — Read, Grep, Glob, Write; verifier — Read, Grep, Glob, Bash, Write. `gh` ревьюерам не нужен;
- **brief по ролям**:

  | Роль | Brief |
  |---|---|
  | executor | файл задачи, тексты правил из `rules` по ID из `docs/design`, строки Q-NN и G-NN задачи, пункты `CONVENTIONS.md` (S0-50) по модулям задачи, ответ владельца |
  | fixer | находки с hunk'ами и текстами их правил, пункты `CONVENTIONS.md` по путям находок, решения владельца; `verify-red` — упавшие test-sets из JSON прогона |
  | reviewer-spec | файл задачи, тексты правил, тело PR, `expectations`, hunk'и оси, `diff.patch`, находки на статус |
  | reviewer-standards | пункты `CONVENTIONS.md` по области hunk'ов, строки ST по классам путей, hunk'и, `diff.patch` |
  | reviewer-architecture | текст `plan/closure-check.md`, строки RM-Z04, сработавшие триггеры, hunk'и, `diff.patch` |
  | verifier | находки, ответы, hunk'и дельты; `range` и `files` для `conflicts` |

  Карта «класс путей → строки ST» — рядом с классами `scope.mjs` (в S0-42 переезжает в классификатор). Глоссарий — Grep по имени, не чтение целиком. Что не вошло в бюджет — `dl` пишет в brief, что отрезал;
- **`dl step <имя>`**: `selfcheck` — по diff ветки, закоммиченному: merge-base с `origin/main`..`HEAD`, как круг ревью: сработавшие триггеры Architecture и опись `closure-check.md` только по ним, пункты `CONVENTIONS.md` по путям, которых не держит проверка, строки таблицы «Правила» PR; пустой список — делать нечего; `pr` — шаблон описания PR из `plan-task`; `deviation` — раздел «Отступления» `plan-task`; `where` — раздел «Что и куда пишет исполнитель» (на него ссылаются тела executor и fixer). Разделы `plan-task` адресуемы по заголовку, `dl` печатает их как есть;
- **тела агентов** (все шесть): роль по карте выше, на каком шаге какой `dl step`, точная схема выхода; файлы читать инструментом Read, не `cat` и не `sed`;
- **`AGENTS.md`**: строка о `plan-task` — «агент `/dev-loop` работает по своему определению и brief; вне цикла — `plan-task`»;
- **`context_missing`** в `out.json` всех ролей: что агенту пришлось прочитать сверх brief и зачем; `dl final` печатает эти строки и размер brief'ов в токенах по оценке;
- **замер**: контекст первого шага executor по транскрипту до и после — цель ≤ 15k токенов вместо 46k. Если MCP-схемы остались при `tools` — `disallowedTools` с шаблонами MCP; не помогло — агенты цикла запускаются не фоном. Итог замера — в описании PR. Определение агента грузится из рабочей копии владельца при старте сессии, поэтому executor с новым определением до merge не запускается: «до» — по транскриптам executor, «после» — по транскриптам ревьюеров, у которых `tools` уже задан, плюс разница тела и инструмента Edit; прямой замер — первый executor после merge;

Не входит: выбор файлов кода для executor — читает то, что меняет или проверяет; шаги 1 и 6 `plan-task` — S0-51; классификатор путей в `scripts/` — S0-42.

## Тесты и фикстуры

- Brief executor несёт текст правил задачи дословно из `docs/design` и только пункты `CONVENTIONS.md`, чья область задевает модули задачи; brief ревьюера Standards — только строки ST классов его hunk'ов.
- Hunk'и оси: brief Spec в круге `full` — hunk'и всех файлов, кроме генерируемых; brief verifier в круге `close` — hunk'и всех файлов дельты и только дельты.
- `dl step selfcheck`: diff без триггеров Architecture не даёт описи; новый экспорт — даёт; diff только в путях, которые держат проверки, — пустой список.
- `dl step pr` и `deviation` печатают разделы `plan-task` дословно.
- Бюджет: brief сверх 15k обрезан, и обрезанное названо.
- `context_missing` из выхода агента попадает в итог `dl final`.
- Тела агентов: у каждого `tools` по карте и схема выхода, совпадающая со схемой `plan/dev-loop.md` (`test/tools/dev-loop-docs.test.ts`).
