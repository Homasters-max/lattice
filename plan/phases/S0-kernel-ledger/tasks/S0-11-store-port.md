# S0-11 · Порт store — адаптеры memory и jsonl, контракт-тесты

## Зачем

Хранилище за портом `store` (LG-02): ledger не знает, где лежат коммиты. В S0 — `memory` для тестов и `jsonl` — git-копия `knowledge` в `store/`. Один набор контракт-тестов на оба (LG-03) гарантирует, что `postgres` в S1 встанет на готовый контракт.

## Объём

Входит:
- **интерфейс** порта для `knowledge` (часть LG-02 S0): `append(commit, delta, evidence)` атомарно; `commits(from)`, `tail()`; строки по ключу и префиксу; `evidence(hash)` — байты как есть (в S0 непрозрачные);
- **`store-memory`**;
- **`store-jsonl`**: `store/knowledge.jsonl` — один коммит на строку, канонические байты; `store/evidence/<hash>.jsonl`; append пишет evidence, затем одну строку одним вызовом записи; обрезанная последняя строка при открытии — отказ с rule ID, не починка;
- **открытие** (LG-02, LG-05): адаптер отдаёт коммиты, ledger проверяет цепочку и подписи (`verifyChain`, S0-10) и сворачивает строки (fold — S0-12; до неё — заглушка) и отдаёт их адаптеру, который держит их в памяти; в git — только коммиты и evidence, никогда строки;
- **контракт-тесты** (LG-03, ST-07): одна сюита на оба адаптера — коммиты, строки, `view(seq)` и evidence побайтно одинаковы.

Не входит: части `runtime` в LG-02 и LG-03 (`seq` и время append, отказ по сроку сертификата, `content(hash)`) и `postgres` (LG-08) — S1 по SL-Z04. Один ledger — `knowledge` (LG-01): второй появляется в S1.

## Шаги

1. Уточнить интерфейс из skeleton; изменение файла skeleton — пометка ST-15 в PR.
2. `store-memory` и контракт-сюита на нём.
3. `store-jsonl` на временном каталоге; та же сюита.
4. Тест обрыва записи: незавершённая строка → открытие отклоняется.

## Готово, когда

- [ ] контракт-сюита зелёная на `memory` и `jsonl`, байты совпадают
- [ ] открытие `jsonl` проверяет цепочку и подписи и отклоняет испорченный файл с rule ID
- [ ] строки проекций никогда не пишутся в git

## Риски и заметки

- Контракт-сюита пишется так, чтобы `postgres` в S1 подключился без её изменения.
- От S0-03 (Q-09, Q-11, Q-25): тонкий `store-jsonl` уже есть — `append({commit, delta, evidence})` пишет одну каноническую строку на коммит в `store/knowledge.jsonl`, `commits` читает с начала; адаптер canon не знает и строк не разбирает: ledger отдаёт строку (`encodeCommit`) и разбирает её сам (`decodeCommit`, `openLines`); строка, которая не коммит, уже отклоняется при открытии — KR-10, LG-06 и KR-04 с путём от строки (ревью S0-03, волна 2). С волны 3 (Q-18, Q-19) `commits` и `tail` отдают байты строк: `store-jsonl` режет файл по `\n`, ничего не декодирует и не выбрасывает — пустая строка и байты не UTF-8 доходят до ledger и отклоняются KR-10; байты после последнего `\n` адаптер отдаёт как строку — обрезанную строку отклоняет эта задача. Порядок ключей строк — `sortRows` из порта. Задача добавляет проверку цепочки и подписей при открытии, отказ на обрезанной последней строке, `store/evidence/`, передачу строк адаптеру при открытии и точные типы порта; контракт-сюита `test/contract/store.test.ts` растёт отсюда.
