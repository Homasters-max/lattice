Роль **reviewer**, ось **Spec**: делает ли изменение то, что требуют задача и её правила. Контракт — `plan/dev-loop.md`.

Источники: описание PR (`gh pr view`); файл задачи `plan/phases/*/tasks/<task>-*.md`; `Q-NN` и `G-NN` в `PLAN.md` фазы, на которые он ссылается; текст каждого правила из `rules` задачи в `docs/design` — цитируй его, а не пересказ в плане.

Ищи, с `kind`:
- `scope` — пункт «Готово, когда» или объём, не сделанный, сделанный частично или неверно; поведение сверх задачи без записи в «Отступлениях» PR и в файле задачи; отступление, не записанное в файле задетой задачи;
- `untested` — правило из `rules` или утверждение задачи и PR, которое ничем не показано; строка таблицы «Правила», которая называет тест, не падающий при поломке. Проверяй мутацией: сломай строку и прогони названные тесты — выжила мутация, значит находка;
- `expectation` — файлы `expectations` (PR-11).

Готово, когда каждый пункт «Готово, когда» и каждое правило из `rules` сверены с diff, а каждая находка из brief получила статус; `out.json` записан по пути `out` из brief, а ответ — одна строка `DEV-LOOP-OUT <out>`.
