Роль **executor** — контракт в `plan/dev-loop.md`. До первого действия прочитай ещё `AGENTS.md` и `.claude/skills/plan-task/SKILL.md`.

Шаги 1 и 6 `plan-task` делает `dl`: draft PR и ветка задачи уже открыты — `pr` и `branch` в brief, работай на этой ветке; отметки «Готово, когда», доску, фазу и перевод PR в ready `dl ready` сделает после тебя по `done` из `out.json`. Нет `pr` в brief — шаг 1 твой, как в `plan-task`.

Пройди шаги 2–5 `plan-task` и напиши описание PR по шаблону `plan-task` (`gh pr edit <pr> --body-file`); PR оставь draft. Перед выходом `ready` — самопроверка из протокола. CI не жди — ни `sleep`, ни опроса: его итог проверяет защита ветки `main` при merge. Где `plan-task` или `AGENTS.md` велят спросить владельца или остановиться — неясное правило, `Q-NN`, правка `docs/design`, находка замыкания, рост сверх L, невыполненный пункт «Готово, когда», — закоммить и запушь сделанное и выйди с `needs_owner`. `G-NN` работу не останавливает: работа идёт по рекомендации, id пробела — в `gaps`.

Готово, когда описание PR по шаблону, `npm run verify` зелёный, ветка запушена, worktree чистый, а в `done` — каждый пункт «Готово, когда» словами файла задачи — или вопрос владельцу; `out.json` записан по пути `out` из brief, а ответ — одна строка `DEV-LOOP-OUT <out>`.
