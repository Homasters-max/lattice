# AGENTS.md

LATTICE — governance substrate: дизайн с правилами по ID в `docs/design`, реализация на TypeScript срезами S0 → SW → S1…S4 (SL-01). Где мы — `plan/STATUS.md`.

## Источники правды

- **Дизайн** — `docs/design`. Утверждение о поведении системы опирается на правило: называй его ID и читай текст правила в файле, а не пересказ в плане.
- **Задача плана** уточняет объём и не меняет правил. Расхождение задачи, кода, теста или своего понимания с правилом — стоп и вопрос владельцу; ответ записывается в `PLAN.md` фазы.
- **Улучшение архитектуры**, замеченное по ходу, — отдельное решение владельца: запиши его в «Открытое» PR, а реализуй архитектуру как она есть.
- **Правка `docs/design`** — только по решению владельца, с записью в `discussion/decisions.md`. Файлы остаются каноническим `md` в LF: от байтов зависит round-trip (LG-42). После правки — `node discussion/tools/lint-ids.mjs`.

## Код

- **Замыкание механизмов** (PR-03, RM-08): код реализует только механизмы RM-Z04. Понадобился новый механизм или обход существующего — стоп и вопрос владельцу. Перед PR — `plan/closure-check.md`.
- Импорты — по матрице ST-01. Вне `adapters`, `assembly`, `cli` код чистый: время, id и внешний мир приходят только через порты (ST-04).
- Каждый отказ называет rule ID; у каждого rule ID жёсткой проверки есть фикстуры trigger и pass (ST-17).
- Имена в коде — термины глоссария `docs/design/00-glossary.md` (ST-03). Соглашения кода — пункты `CONVENTIONS.md` `§N.M`. Новое соглашение — сначала проверка, чей отказ называет норму (ST-16); пункт — только если проверка невозможна.
- Красный тест или отказ — вход для следующего шага (PR-11): найди причину. Ожидания тестов, фикстуры и проверки меняются только вместе с правилом.
- Генерируются и руками не правятся: `gen/`, `store/knowledge.jsonl`, `plan/phases/*/RULES.md`, после переключения — `docs/` (AG-11).

## Язык

`docs/design`, блоки знания, идентификаторы и всё, что читает LATTICE, — английский (PR-14). План, `discussion/`, описания PR — русский.

## Зелёный

`npm run prove` — с S0-42: шаги `verify` без тестов, весь fitness и test-sets, чей hash входа изменился против `origin/main` (`--base <ref>` — другая база). Итог — `outcome` в JSON последней строки и код выхода; вывод не режется `| tail`, полный лог — `.lattice/prove.log`. `npm run verify` — полный прогон, для CI и владельца.

## Задача плана

Агент `/dev-loop` работает по своему определению и brief; вне цикла работа над задачей плана (`S0-04` и т. п.) идёт по `.claude/skills/plan-task/SKILL.md` — прочитай его до первого изменения. Цикл «исполнитель → ревью → исправления» целиком ведёт `/dev-loop`; что блокирует merge и контракт агентов — `plan/dev-loop.md`. Он же задаёт формат PR и отчёт о ходе работы; навыки WARRANT (`pr`, `progress`) к этому репозиторию не относятся (D3).
